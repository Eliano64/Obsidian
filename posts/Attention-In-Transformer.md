# 序列中的信息读取

Attention 计算序列中不同位置 Token 之间的匹配关系，再按匹配程度读取并汇总信息，为每个 Token 生成新的上下文表示。

循环网络靠隐藏状态沿时间步传递信息。句尾要读句首，必须经过中间一连串隐藏状态，路径随序列变长；同一层的不同位置也不能同时计算。自注意力让每个 Token 用自己的查询直接匹配整个序列的键，再汇总值，任意两个位置之间只有一步。

在进入注意力之前，每个 Token 的向量主要表示自身的语义与位置。经过注意力之后，新向量已经融合了序列中其他相关位置的信息。向量的形状不变，变化的是内容。自注意力的输出序列长度与输入相同。

![注意力前后：向量形状不变，内容改变|631](../assets/attention-before-after.svg)

一次注意力计算分为三步：打分、归一化、加权求和。通用形式见 [[Attention#打分、归一化与加权|一次注意力计算]]。

# 三类注意力

Transformer 使用三种注意力。它们的计算过程相同，区别在查询、键、值分别来自哪里。

自注意力在编码器中，每个位置都能看到整个输入序列。掩码自注意力在解码器中，每个位置只能看到自身及之前的位置。交叉注意力的查询来自解码器，键与值来自编码器的最终输出。

| 类型 | 查询来自 | 键与值来自 | 作用 |
| --- | --- | --- | --- |
| 自注意力 | 输入序列 | 输入序列 | 生成输入序列的上下文表示 |
| 掩码自注意力 | 输出序列 | 输出序列 | 生成当前输出前缀的上下文表示 |
| 交叉注意力 | 解码器 | 编码器 | 根据当前生成状态读取输入序列 |

# 自注意力

编码器使用自注意力处理输入序列。每个位置既发起查询，也提供键和值。因此每个位置都能观察整个序列，并根据与其他位置的关系重新生成表示。

对每个查询，先与所有键做点积，得到匹配分数。分数除以 $\sqrt{d_k}$ 缩放，$d_k$ 是当前注意力头中查询与键的向量维度。缩放后的分数经过 Softmax，成为一组和为 1 的权重。把各位置的值按行组成矩阵 $\mathbf{V}$，把权重按行组成矩阵 $\mathbf{A}$。最后按权重汇总所有位置的值：

$$
\mathbf{A}=\operatorname{softmax}\left(\frac{\mathbf{QK^{\top}}}{\sqrt{d_k}}\right),\qquad
\mathbf{O}=\mathbf{A}\mathbf{V}
$$

$\mathbf{A}$ 的第 $i$ 行、第 $j$ 列，是第 $i$ 个位置更新自身表示时分配给第 $j$ 个位置的权重。$\mathbf{O}$ 的每一行，是一个 Token 融合上下文后的新表示。缩放的原因见 [[Attention#缩放|点积分数的缩放]]。

例如在句子「The animal didn't cross the street because it was too tired」中，代词 it 在更新自身表示时，与 animal 的匹配程度最高，与 street 等位置也有一定匹配。

![代词 it 对各位置的注意力权重|631](../assets/attention-example-lines.svg)

# 掩码自注意力

解码器在训练时一次收到完整的目标序列。不加限制时，前面位置在更新表示时可以直接读取后面的正确答案，训练因此失去意义。

## 因果掩码

解决这个问题的办法是采用**因果掩码 Causal Mask** 。把每个位置可见的范围限制在自身及之前。匹配分数矩阵的右上三角被置为 $-\infty$，对角线与下三角保持不变；第 $i$ 行只有第 $j\le i$ 列参与 Softmax。掩码矩阵的边长等于序列长度。这样，即使一次读入完整目标序列，每个位置也只能根据自身及之前的目标前缀预测下一个 Token，与推理时逐 Token 生成一致。推理时未来 Token 尚未产生，本来就读不到；掩码主要解决训练阶段一次读入完整目标序列时的信息泄露。

在匹配分数上加入掩码矩阵 $\mathbf{M}$：允许关注的位置取 0，需要遮挡的位置取 $-\infty$。经过 Softmax，被遮挡位置的权重变为 0：

$$
\operatorname{Attention}(\mathbf{Q},\mathbf{K},\mathbf{V})
=
\operatorname{softmax}\left(\frac{\mathbf{QK^{\top}}}{\sqrt{d_k}}+\mathbf{M}\right)\mathbf{V}
$$

# 交叉注意力

掩码自注意力之后，解码器已经形成当前输出序列的上下文表示，但还需要回到输入序列读取预测下一个 Token 所需的信息。交叉注意力完成这一步。

交叉注意力的查询来自解码器的当前序列表示 $\mathbf{Z}$，键与值来自编码器的最终输出 $\mathbf{H}$：

$$
\mathbf{Q}=\mathbf{Z}\mathbf{W}_Q,\qquad
\mathbf{K}=\mathbf{H}\mathbf{W}_K,\qquad
\mathbf{V}=\mathbf{H}\mathbf{W}_V
$$

因此查询与键、值来自两个不同的序列。编码器的输出只计算一次，解码每一步复用。解码器根据当前已经生成的内容形成查询，再用它查询编码器对输入序列的表示，得到预测下一个 Token 所需的源序列信息。

# KV Cache

推理是自回归的：每生成一个 Token，把它追加到已生成的输出序列，再生成下一个 Token。每一步都要执行一遍注意力。如果每一步都重新计算历史位置的键与值，计算量会随序列长度重复累积。

KV Cache 把历史 Token 在每一层注意力中已经生成的键与值保存下来，生成下一个 Token 时直接复用。缓存的代价是显存占用随序列长度与层数增长。KV Cache 只影响推理阶段，训练时并不使用。

交叉注意力的键与值来自编码器的最终输出。输入序列在整个解码过程中不变，这部分键与值可以提前计算，并在每一步解码时重复使用。

掩码自注意力的键与值随生成过程增长。每生成一个新 Token，解码器只需计算新位置的查询、键、值，再把新的键与值追加到缓存中，过去位置不需要重新计算。

> [!question] 为什么查询不缓存
> 第 $t$ 个位置只产生一个查询 $\mathbf{q}_t$，它只用于本次查询。生成下一个 Token 时会产生新的查询，过去的查询不会再次使用。键与值则作为历史信息被后续位置持续读取。

KV Cache 发生在一次生成过程内部。Prompt Cache 跨请求复用相同 Prompt 前缀的计算结果，减少相同前缀被反复处理的时间与计算成本。两者依赖同一个事实：每个位置的中间状态都依赖它之前的内容。前缀越稳定，可以复用的范围越大。因此在 Agent 开发中，稳定的系统提示词、工具定义与公共上下文通常放在 Prompt 前部，经常变化的用户输入放在后部。
