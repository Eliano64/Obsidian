# 决策树的位置

[[Logistic-Regression|逻辑回归]]这类模型把样本的所有特征乘上权重再加起来，一次算出一个分数，训练就是调整这组权重，让分数更接近标签。决策树换了一种做法：对当前这批样本提一个问题，按答案把样本分到不同的子集，再对每个子集继续提问。

这些判断构成一棵倒立的树：问题在内部节点，答案沿分支传递，结论落在末端的叶子上。建树要做的决定只有一个：每一步挑哪个特征来问。判断一个特征挑得好不好，靠的是纯度（节点里样本在类别上有多一致）。

# 层层提问的结构

决策树（Decision Tree）以逐层提问的方式划分数据：按不同特征递归分裂，最终形成倒立的树状结构。三个部件构成一次推理的完整链条：

| 部件     | 在树中的位置         | 代表的内容                                             |
| -------- | -------------------- | ------------------------------------------------------ |
| 内部节点 | 分叉处               | 对某个特征的判断问题，例如“天气是晴天吗”               |
| 树枝分支 | 从节点引出的每一条线 | 判断得到的一个答案，例如“是”与“否”，一条分支对应一个答案 |
| 叶节点   | 不再分叉的末端       | 最终的决策结果，例如“去打球”或“不去”                   |

从根节点到某个叶节点，沿途的每一次判断连起来就是一次完整的推理，这条路径同时是模型给出该结论的依据。决策树的可解释性来自这里：每一步都是关于某个特征取值的判断，而不是多项加权求和。

这一点与[[Logistic-Regression|逻辑回归]]形成对照。逻辑回归也输出一个概率，但概率来自全部特征权重的一次加权求和；要说明某个样本为什么被判成这一类，只能回到系数上逐个解释每个特征的贡献。树的判断路径不需要换算。

# 每次分裂的选择

树的结构确定之后，预测就很直接：从根开始，每一步看一个特征，到达叶子就得到答案。真正的工作量在训练，而训练要解决的只有一个问题：当前这个节点该用哪个特征来问。天气、温度、湿度都能当候选，第一步选错，后面的分裂只能在次优的子集上补救。

模型判断第一步该问天气还是温度，需要一个能比较两个候选划分好坏的数，这个数建立在纯度之上。

## 纯度

**纯度**（Purity）衡量一个节点里的样本在类别上有多一致：全部同属一类时纯度最高，各类比例相等时不纯度最高。分裂的目的是让子节点比父节点更纯，一次分裂值不值得做，取决于划分把纯度提高了多少。

纯度是判断标准，还不是可计算的量。下面两套指标都在做同一件事：把纯度换成数值。

## 熵

熵（Entropy）衡量一个节点中各类别分布的混乱程度。记当前节点为 $D$，$K$ 为类别数，$p_k$ 为该节点中第 $k$ 类样本的比例，熵定义为：

$$H(D) = -\sum_{k=1}^{K} p_k \log_2 p_k$$

某一类的比例为 0 时约定 $0 \log 0 = 0$：这一类在节点里不出现，不贡献混乱程度。以 2 为底时，熵的单位是比特。

两类各占一半（$p_1 = p_2 = 0.5$）时，$H = -(0.5 \times (-1) + 0.5 \times (-1)) = 1$ 比特，这是两类问题里熵的最大值，也就是最难判断样本类别的状态。一类占满（$p_1 = 1$，其余为 0）时 $H = 0$，没有不确定性，最为纯净。

计算开销落在对数上。建树时每评估一个候选划分，都要对每个子节点按类别算一遍 $p_k \log_2 p_k$；候选划分的数量随特征数与取值数增长，对数运算的次数随之增长。实际开销取决于实现与候选数量，对数运算通常是评估中较重的一环。

## 信息增益

信息增益（Information Gain）定义为用某个特征分裂之后混乱程度下降了多少，也就是这次分裂消除了多少不确定性。按特征 $A$ 把父节点 $D$ 分成 $m$ 个子节点 $D_1, \dots, D_m$，分裂后的混乱程度是各子节点的熵按样本比例加权求和：

$$H_{\text{after}}(D, A) = \sum_{i=1}^{m} \frac{|D_i|}{|D|} H(D_i)$$

加权这一步不能省。子节点的样本数不同，一个只装三个样本的纯子节点和一个装了几百个样本的纯子节点，对父节点混乱程度的削减不同；用 $|D_i|/|D|$ 把权重归一到 1，分裂后的值才与分裂前的熵在同一尺度上。

$$\mathrm{IG}(D, A) = H(D) - \sum_{i=1}^{m} \frac{|D_i|}{|D|} H(D_i)$$

增益越大，说明这个特征把不同类别分开的能力越强。建树时对所有候选特征各算一次增益，取最大的那个去分裂。

## 基尼不纯度

基尼不纯度（Gini Impurity）是另一套纯度度量，动机是计算更快：熵要为每个子节点算对数，基尼不纯度只用乘法和加法。基尼不纯度与经济学中衡量收入分配的基尼系数不是同一个指标，只是名称相近。

直观含义可以一句话说清：随机从节点中抽取两个样本，两者属于不同类别的概率。抽完放回，两次抽取的分布相同。两次抽到同一类的概率是各类比例的平方和 $\sum_k p_k^2$，两次抽到不同类的概率是：

$$Gini(D) = 1 - \sum_{k=1}^{K} p_k^2$$

另一种写法从第一个样本出发：第一个样本属于第 $k$ 类而第二个不属于，概率是 $p_k(1 - p_k)$，对 $k$ 求和即两次抽到不同类的概率：

$$Gini(D) = \sum_{k=1}^{K} p_k(1 - p_k)$$

两式恒等，因为 $\sum_k p_k = 1$：把第二式展开成 $\sum_k p_k - \sum_k p_k^2$，第一项正是 1。两条公式表达的是同一个量的两种写法，不是两式相除。

用具体的分布验算。两类各占一半时 $p_1 = p_2 = 0.5$：第一式给 $1 - (0.25 + 0.25) = 0.5$，第二式给 $0.5 \times 0.5 + 0.5 \times 0.5 = 0.5$。按概率直接算也一样：先抽到第一类再抽到第二类的概率是 $0.5 \times 0.5 = 0.25$，顺序反过来再得 0.25，合计 0.5。

一类占满时 $p_1 = 1$，其余为 0：第一式给 $1 - 1 = 0$，抽两次必然同类，概率为 0，节点完全纯净。

再看三类等分，$p_1 = p_2 = p_3 = 1/3$：第一式给 $1 - 3 \times (1/9) = 2/3$，两次抽到同类的概率是 $3 \times (1/9) = 1/3$，不同类就是 $2/3$。同样的均匀分布，类别越多这个值越大：两类最多 0.5，三类最多 2/3，所以跨不同类别数的节点不能直接比较基尼不纯度。

实践中更常用基尼不纯度，原因在计算：只有乘法和加法，没有对数；建树时每个候选划分都要算一次。scikit-learn 的决策树（CART 算法）默认指标是基尼不纯度。使用时该值越小，节点越纯。

## 两种指标的取舍

两套指标的形状接近：都在纯净时取 0，都在均匀分布时取最大，在多数节点上选出的划分相同。差别在尺度和代价上：

| 对照项           | 熵                                                   | 基尼不纯度                                   |
| ---------------- | ---------------------------------------------------- | -------------------------------------------- |
| 衡量的东西       | 节点中类别分布的混乱程度                             | 随机抽两个样本、类别不同的概率               |
| 两类各半时的取值 | 1 比特                                               | 0.5                                          |
| 均匀分布时的最大 | $\log_2 K$，随类别数增长较快                         | $1 - 1/K$，增长较慢                           |
| 单次计算         | 每类一次对数                                         | 每类一次乘法与加法                           |
| 适用场合         | 需要与信息论的量对照、要解释“消除了多少不确定性”时用 | 大规模建树的默认，速度优先时用               |

分工大致如此：需要把“这个特征消除了多少不确定性”讲清楚，就用熵与信息增益；需要在一批候选特征里快速比较，就用基尼不纯度。两套指标的尺度不同，因此在同一个节点上可能选出不同的划分，树的结构不保证完全一致。

# 建树的递归算法

指标确定之后，建树是一个递归过程：在当前节点上选一个特征划分，再对划分出的每一部分重复同样的事。下面五步是一个节点上要做完的全部工作。

1. 计算指标：在当前节点上，分别用每一个可用特征划分，算出各子节点按样本比例加权后的基尼不纯度。
2. 选择最优：取划分后基尼不纯度最小、也就是纯度提升最大的那个特征。
3. 分裂数据：按该特征的不同取值把样本分成若干份，每一份成为一个子节点。
4. 递归生长：对每个子节点重复上述过程，继续向下生长。
5. 生成叶节点：满足停止条件时不再分裂，确定该节点的最终预测结果。

第一步算出每个候选划分的指标，第二步在这些数里取最小；第三步只按选中特征的取值分样本，其他特征不参与；第四步把前三步交给每个子节点，子节点只使用自身那份样本。

递归必须有出口。节点的样本已经同属一类时，熵与基尼不纯度都已到 0，再分不会带来提升；找不到能让纯度提升的划分时，继续分只会把样本摊薄成孤点。这两种情况下当前节点直接变成叶节点，用样本中占多数的类别作为预测结果。

# 剪枝

不加约束时，决策树会为把每一个异常值都分对而长出大量分支：某条分支只为那一个离群样本存在，叶节点只包含该样本。这样的树在训练集上几乎不出错，但那些分支描述的是这一批样本的偶然，对新样本的预测能力可能下降，这种现象称为过拟合。

对策是剪掉多余细节，保留核心结构。按动手的时机，剪枝分两类。

## 预剪枝

预剪枝（Pre-pruning）在树向下生长的过程中提前设定规则，触及规则就停止。常用的两条规则是限制最大深度（max_depth）和限制叶节点最少样本数。

这种方式实现简单、计算量小，工业界广泛使用：规则在分裂之前就起作用，不需要先生成一棵大树，深度与叶节点样本数都是建树时可直接检查的量。

> [!warning] 预剪枝看不到深处的收益
> 代价来自规则的短视。规则只看当前节点；当前这次分裂看起来不值得做，不等于再往下两层不会出现有价值的划分。预剪枝在那一刻停止，深处的结构再也长不出来。预剪枝的判断是对未来的估计，不是对完整树实际表现的比较。

## 后剪枝

后剪枝（Post-pruning）先让树生长到最大，再从下往上检查，把某个子树换成一个叶节点，比较换掉前后的误差；误差不变或更小就剪掉这个子树。

判断因此发生在完整树的实际表现上：子树有多深、切出了哪些分支都已知道，剪与不剪可以真正比较一次。这使判断依据更充分，但不保证剪枝后的树一定更好；如果用于比较的验证数据与真实分布有偏差，剪枝结果同样可能偏离。

代价是计算。必须先生成一棵完整的树，再对每个子树做一次替换检查，大数据下这个成本可能超过剪枝带来的收益，这也是工业界仍然大量使用预剪枝的原因。

| 对照项     | 预剪枝                                       | 后剪枝                                     |
| ---------- | -------------------------------------------- | ------------------------------------------ |
| 动手时机   | 生长过程中，规则一触发就停                   | 树长到最大之后，从下往上回剪               |
| 判断依据   | 最大深度、叶节点最少样本数这类预设规则       | 把子树换成叶节点前后的误差比较             |
| 计算成本   | 低，不必生成完整树                           | 高，要先生成完整树再逐个检查子树           |
| 主要问题   | 规则看不到深处的收益，可能过早停止           | 大数据下耗时，成本可能超过收益             |

# 表格数据的基线

> [!tip] 表格数据先建立一棵树作为参照
> 实战经验：表格数据先建立一个树模型基线，通常是稳妥的起点。这里的基线指一个简单、稳定、结果可复现的参照模型，后续更复杂的模型与这个参照比较；表格数据则是每行一个样本、每列一个特征的数据，连续特征通常可直接使用，类别特征是否需要编码取决于具体实现。

第一件是成本。建树只用到比较与乘加，常用的超参数包括深度、叶节点最少样本数和划分指标，执行一次就有结果，建立参照的代价很低。

第二件是预处理。分裂按阈值切分，特征的量纲不影响切在哪里，所以[[Data-Preprocessing|标准化]]对树不是必需的一步；线性模型通常要先做缩放才能稳定训练。

第三件是可解释。[[Model-Evaluation|评估]]时，参照模型有助于判断指标变化的实际意义，树给出的正是一个可以逐条读的参照；路径还能当检查工具：如果树把一个业务上明显无关的列放在根节点，多半是数据泄漏或编码错误。

基线不是终点。单棵树的方差偏大，样本换一批，结构就可能变；基线不足时，可以改用[[Ensemble-Learning|集成方法]]。换用更复杂的模型之前，先用同一份评估数据确认新模型相对这棵树的差距，否则多出来的复杂度只增加维护成本。
