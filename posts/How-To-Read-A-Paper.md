# 价值判断

读一篇论文之前，先判断值不值得读，再决定读多深。

判断只需要读三处：Abstract、所有图的图注、结论段最后三句。判据只有一条：这篇论文会不会改变眼下的某个决定，或者自己是否打算照它的方法动手做一遍。答案是否，记一行出处就停下。多数论文都该停在这里，这是常态。

停之前再做两项检查。一是它有没有过时：翻最近三年引用它的论文，看还有没有人把它当对手做实验。二是它的结论能不能自己验证：方法型看代码，理论型看证明，数据集型看构建流程与划分方式。两项都不成立时，它只算一条文献线索。

# 阅读深度

由用途决定，三种深度对应三种产出。

只想引用一个结论，读主结果表里自己方法那一行、Abstract 末句与结论段末三句。摘要末句常常只是口号，真实的数字在主表里。产出一句同时带数字、数据集和条件的话。

打算在自己方案里采用它的方法，读方法部分与总图、实验设置和消融表。要能复述输入、变换与输出，还要说出它成立依赖哪些前提。产出是一段机制描述和一份适用边界。

打算在它基础上修改或反驳，读全文，包括推导与附录。要重推删掉之后结论就不成立的那一步，核对实验设计，必要时做小规模复现。产出是一份能照做的最小实现说明，或一份指出结论在什么地方失效的分析。

浅的一级读到的内容，在深的一级里仍然要用。引用时写下的那句断言，正是采用时要验证的对象。

# 按类型调整

不同类型读的地方不同，跳过的部分也不同。

方法型论文的贡献是机制。读机制图、消融表和与最强基线的对比；相关工作可以跳过，形式化的铺垫要读到它引入假设的那一段。

理论型论文的贡献是定理。读定理陈述、它依赖的假设和证明的关键几步；冗长的技术引理可以跳过。

综述型论文的贡献是组织方式。读它的分类框架和各类工作之间的差别；具体的实验数字可以跳过。

数据集与基准论文的贡献是数据。读构建流程、标注一致性、划分方式和已知偏差；排行榜名次可以跳过。

系统与工程论文的贡献是约束。读瓶颈在哪里、负载假设与成本结构；只影响绝对吞吐、不影响对比公平性的调参细节可以跳过。

# 建立框架

多数研究论文按说服顺序编排：结论先出现，支撑它的机制、证据与前提散在各节，中间还夹着只对同行有意义的细节。顺着页序读，时间花在铺垫和实验参数上，读完仍说不出论文主张什么，也说不清依据在哪里。

论文里真正决定结论的只有五项：问题、断言、机制、证据、边界。

建立框架不需要通读，三个动作就可以：看目录，读每节的首末两句，读每一张图表。

1. 先看目录。方法型论文通常只有引言、方法、实验三个实质章节，其余是相关工作、实现细节与附录。先读引言末段和主结果表，再读方法那一节。

2. 然后照着目录，把论文里每一节过一遍。论文用带编号的标题分节，3 Method 是方法这一节，3.1 Setup 是它下面的小节。每节只读第一句和最后一句，小节先跳过。作者习惯把结论放在节末，把要回答的问题放在节首。

3. 最后读每一张图表。先看注，知道这张图表在说什么；再看图表本身，横轴纵轴是什么量、纵轴是不是对数刻度、误差条是一次运行还是一组种子，这些只有图上才有；最后读正文里引用它的那句话，作者通常已经写好了想让你看见的结论。

把结果写成六行：

```text
问题：既有方法在何种现象上失效
断言：论文声称达到的结果，可量化的部分
机制：得到该结果的做法，一句话，不写公式
关键证据：哪一个实验一旦不成立，断言随之不成立
边界：作者承认的失效条件
借用：能从这里拿走什么？可借鉴的方法、模块或实验设置；没有就写没有
```

# 术语与记号

只记读下去会卡住的词。先分清它是作者新造的说法，还是这个领域通用的词：前者继续读，后者说明前置知识不足，可以先去读综述或教材的相应章节。

每个术语的定义必须取自论文。凭常识补出来的意思如果和作者不同，后面的推理就全建在错误前提上。

公式先看形状，再看运算。相乘时左张量的最后一维要等于右张量的倒数第二维，逐元素相加时形状要一致，不一致就按长度为 1 的维度补齐。形状看清楚了，数据怎么流动也就清楚了。

读到断言句时留意动词和形容词的分量。show、demonstrate 后面通常有实验或证明；observe、find、suggest 只承诺某一种设置下的现象；argue、believe 是作者判断；can、may、hypothesize 是未经检验的提议，读到这类词记下缺失的证据。significant 只说明两组真有差异时出现这么大差距并不容易，并不说明效果大；outperform、substantially 后面没有数字时，应到主结果表中查对应的数值。

# 主论证精读

打算在自己的方案里采用它的方法，或者要修改、反驳它时，才做这一步。全文只有三处值得逐句读。

第一处是断言句，一般在引言末段或主结果表上方。读到能用自己的话复述，且复述里带得出数字和条件。摘要末句常是口号，不能单独当断言。

第二处是机制段，通常是方法的核心，往往夹着公式，也有整节不用公式的论文。读到能复述输入、变换与输出。推导不必逐行重算，但要停在作者丢掉的项上：哪一项被当成小量，哪个分布被假定不变，哪一步默认了求和与期望可以交换。这些被丢掉的项就是结论成立的前提。理论型论文的证明不能跳过，适用条件几乎都写在开头引入假设的那几句。

第三处是支撑这条断言的那个实验。读到能说清它排除了哪一种替代解释。同一个差值可以有很多种解释，实验设计的作用就是把其余解释排除掉。

# 段落分类

三处之外的段落，第一遍只扫标题、开头一句和结论一句，再按下面几类分别处理。

复现细节第一遍跳过，复现时再回来查。但基线与本文方法的设置差异要读，两者是否用同样的增强、同样的调参预算，决定了对比是否公平。

we also tried but did not help 这类句子是负面结果，它们来自作者的实测，价值很高，记在卡片边界行下面，不要和失效条件混在一起。它们只对作者的设置成立。

相关工作第一遍跳过，只记作者点名的最强基线模型，和这篇论文想取代的那篇前作。

附录的证明和补充实验是边界的来源，也需要阅读。

消融表看它怎么排。每行从完整模型删掉一个部件时，差值只在部件互不影响时才等于该部件的贡献；每行在上一行基础上继续删时，只有相邻两行之差有意义。差值小于种子波动的，不要当成该部件的贡献。

读不懂一段时，先看它在讲结论还是讲过程。讲过程的可以跳过，但要确认后文没有用到它定义的符号。

# 结果置信

看对照。比较的对象是不是最强基线，它的训练与调参预算是不是和本文方法相当。基线用更少的算力或未调参的默认配置跑出来的，差值里就有一部分是基线自己掉下来的成绩。

看差值。差值要大于换随机种子带来的波动，才值得当成结论；只报一次结果的论文，只有在测试样本足够多时，小差值才站得住。一张表里比较几十个格子时，总会出现一两个看起来更好的，只认摘要点出的主指标。

看边界。作者讨论失效条件的地方通常在 Limitations、Discussion 或附录的补充实验里。全文都找不到，可能是没写，也可能是方法确实成熟，两种都记下来。

# 复现与借用

复现或借用机制时，不必从头读。直接在正文里搜机制的名字或超参，跳到实现那一节，先把实现跑通。论证部分此时不是重点，但复现失败往往恰恰来自论证里省略的细节，预处理、初始化、评测口径都可能在里面，所以对齐数字之前还要回头读方法节。

复现先用作者的代码，在小数据切片上跑通，再对齐指标。对不上时先查预处理和随机种子，再怀疑方法本身。

产出是一份别人能照着做的最小实现说明，和一份边界清单。

# 自检三问


*论文要解决的具体失效现象是什么，现有方法在哪种场景下不成立、在哪种场景下能用但代价太高？*

*它的机制比最简版本多了什么？* 最简版本是本文方法去掉待考察部件、其余设置不变的那个版本，通常就是消融表里的一行。要问的不是哪个更好，而是它多了什么。

*把这套机制搬到自己的场景，哪一个前提会最先失效？*

前两问关于论文本身，答不出就回到对应位置重读。

答完第三问，论文才变成自己的知识。
