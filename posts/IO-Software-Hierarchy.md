# I/O 软件层次

I/O 软件把用户请求逐层转换成硬件能执行的操作。越上层越接近用户，越下层越接近硬件。

![1000](../assets/os-io-software-layers.svg)

> [!note] 驱动程序与中断处理程序为何分成两层
> 在 408 的功能分层模型中，设备驱动程序负责发出设备相关命令，中断处理程序负责接住硬件异步事件，因此把中断处理列为更靠近硬件的一层。具体操作系统常把某设备的中断处理函数实现为该设备驱动模块的一部分。两种说法观察角度不同：前者按**执行职责**分层，后者按**代码归属**分模块。

| 层次 | 位置 | 主要作用 |
| --- | --- | --- |
| 用户层软件 | 用户态 | 提供库函数或用户接口，把用户请求转换成系统调用 |
| 设备独立性软件 | 内核态 | 提供统一 I/O 接口，完成设备保护、差错处理、设备分配、缓冲区管理、逻辑设备名映射 |
| 设备驱动程序 | 内核态 | 把通用 read/write 请求转换成特定设备能执行的寄存器操作 |
| 中断处理程序 | 内核态，最靠近硬件 | 响应设备中断，读控制器状态，完成中断应答和少量紧急处理 |
| 硬件 | 控制器和设备 | 执行实际 I/O 操作 |

> [!tip] 判断属于哪一层
> 直接涉及设备寄存器、设备状态位、设备厂商规定的控制细节，属于**设备驱动程序**。
> 不关心具体硬件、对多类设备都需要的统一的管理工作，属于**设备独立性软件**。

# 用户层软件

用户层软件给用户程序提供更方便的接口。用户程序通常不直接组织内核内部的 I/O 请求，而是调用库函数或系统调用封装。

例如输出文本时，程序可能调用 `printf`。用户层库函数会把格式化输出转换成 `write` 一类系统调用，再进入内核 I/O 软件。

# 设备独立性软件

设备独立性软件也叫设备无关性软件。它屏蔽具体设备差异，对上提供统一接口。

常见功能：

| 功能 | 含义 |
| --- | --- |
| 统一调用接口 | 向上提供 `read`、`write`、`open`、`close` 等统一接口 |
| 设备保护 | 检查进程是否有权访问设备，防止非法 I/O |
| 差错处理 | 对可统一处理的设备错误做重试、报告、恢复或失败返回 |
| 设备分配与回收 | 按设备状态、控制器状态、通道状态决定能否分配 |
| 缓冲区管理 | 用内存缓冲区协调速度差异、传输单位差异 |
| 逻辑设备名映射 | 建立逻辑设备名到物理设备名、驱动入口的映射 |

设备独立性带来的效果是：用户程序不必知道“到底是哪一台打印机、哪个控制器、哪个状态位表示忙”。用户只面对逻辑设备名和统一调用接口。

缓冲、设备分配、逻辑设备名映射和 SPOOLing 等具体机制见 [[Device-Independence|设备独立性]]。

# 设备驱动程序

设备驱动程序负责具体设备控制。上层按照[[Device-Independence#设备驱动程序接口|设备驱动程序接口]]发来统一请求，驱动程序再把它翻译成该设备控制器能理解的寄存器操作。

驱动程序通常要做：

- 设置控制寄存器，如启动读写、设置方向、允许中断；
- 检查状态寄存器，如忙、空闲、就绪、错误；
- 从数据寄存器取数据，或向数据寄存器写数据；
- 按设备厂商规定解释状态位和控制位；
- 与中断处理程序配合，完成异步 I/O。

可见，设备驱动程序是操作系统通用 I/O 请求与具体控制器命令之间的**翻译器和执行者**：向上实现内核规定的接口，向下控制设备并接收设备事件。

> [!important] 物理存在不等于对操作系统可用
> 设备是否物理存在由硬件连接决定；操作系统能否使用它，还取决于系统能否识别设备、是否有匹配且已加载的驱动程序、资源是否配置成功以及设备是否处于可工作状态。缺少驱动不会让设备“消失”，但会使操作系统无法通过正常 I/O 路径使用它。

不同设备需要不同驱动程序，是因为控制器设计不同：寄存器数量可能不同，状态位含义可能相反，命令格式和时序也可能不同。设备独立性软件不能假设所有设备都有同一套寄存器约定。

普通应用程序和系统程序通常运行在用户态，通过系统调用请求 I/O，不直接接触设备寄存器。设备驱动程序则通常运行在内核态，可以直接访问控制器并处理中断。因此它具有三个突出特点：

- **与具体硬件相关**：必须理解设备寄存器、命令和时序，同时遵守操作系统规定的驱动程序接口；
- **并发且由事件驱动**：请求提交、设备完成和中断可能发生在不同执行上下文中，驱动程序必须正确同步共享状态；
- **出错影响范围大**：驱动程序拥有较高权限，错误不仅会使某个程序失败，还可能破坏内核状态或导致整个系统崩溃。

# 中断处理程序

当设备完成 I/O 或发生错误时，控制器向 CPU 提出中断请求；CPU 转入内核后执行相应中断处理程序。

I/O 中断处理程序通常做：

1. 从控制器读出设备状态。
2. 判断 I/O 是否正常完成。
3. 若异常，按原因处理，例如重试、报告错误、唤醒等待进程并返回错误。
4. 若正常，从设备或控制器读入数据，或确认 DMA/通道传送已经完成。
5. 更新内核 I/O 请求状态。
6. 唤醒等待该 I/O 的进程，或通知上层继续后续处理。

异常与中断处理流程见 [[Exception-And-Interrupt-Handling]]。
