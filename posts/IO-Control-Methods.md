# I/O 控制方式

I/O 控制方式，是指系统如何在 CPU、I/O 控制器和设备之间分配控制与数据传送工作，以完成设备与主存之间的数据交换。

同一 I/O 读写任务可以采用不同控制方式。按下文顺序，CPU 直接参与越来越少，硬件承担的工作越来越多，并行性也越来越强。

![1000](../assets/io-control-methods-overview.svg)

# 程序直接控制方式

程序直接控制方式是由 CPU 执行 I/O 程序，直接决定何时访问控制器，并亲自搬运每个传送单位。按照 CPU 在传送前是否需要查询设备状态，可分为**无条件传送**和**条件传送**。

## 无条件传送方式

无条件传送接口不记录供 CPU 查询的“就绪”或“完成”状态。程序认为设备在规定时刻已可传送，到时直接执行 I/O 指令读写数据端口。

这种做法的前提是设备的启动时机和工作节拍可以预先确定，CPU 能够保证访问时设备已准备好。它适合按固定节拍读写设备的巡回采样系统、过程控制系统，以及由程序启动或启动时刻可预知的字符设备。

## 条件传送方式

当设备就绪时间无法预先确定时，接口用状态寄存器或状态触发器记录“就绪”、“完成”等状态。CPU 先查询状态，只在满足传送条件时才访问数据端口，因此条件传送也叫**程序查询方式**。

以输入为例：

1. CPU 向控制器发出读命令，控制器启动设备。
2. 控制器把状态寄存器置为“未就绪”或“忙”。
3. CPU 读取状态寄存器，查询设备是否准备好。
4. 设备把数据送入控制器的数据寄存器，并把状态改为“就绪”。
5. CPU 发现就绪后，从数据寄存器读入一个字或字符。
6. CPU 把数据写入主存；若还要继续输入，再发下一次读命令。

查询又有两种组织方式：

- **独占查询**：CPU 在设备就绪前一直循环查询该设备，查询期间不执行其他工作。
- **定时查询**：CPU 按一定时间间隔查询设备，两次查询之间可以执行其他工作。

两种方式的共同点是，数据都要通过 CPU，通常每次传送一个字或字符：

- 读数据：设备 $\rightarrow$ 控制器 $\rightarrow$ CPU $\rightarrow$ 主存。
- 写数据：主存 $\rightarrow$ CPU $\rightarrow$ 控制器 $\rightarrow$ 设备。

程序直接控制的硬件简单，但每次传送都要 CPU 介入。无条件传送依赖对设备时序的准确判断；条件传送虽然能确认设备已就绪，但查询会占用 CPU 时间，独占查询尤其会使 CPU 长时间忙等。

# 中断驱动方式


中断驱动方式的关键词是**设备完成后主动通知 CPU**。

CPU 发出 I/O 命令后，不再反复轮询状态寄存器，而是去执行其他程序。设备准备好数据或完成一次传输后，控制器向 CPU 发出中断请求。CPU 响应中断后转入操作系统内核中的中断服务程序，由服务程序完成数据搬运和后续处理。

中断驱动读操作的大致流程：

1. CPU 向控制器发读命令，等待该 I/O 的进程可被阻塞。
2. CPU 切换去执行其他程序。
3. 设备准备好一个字或字符后，控制器提出中断请求。
4. CPU 在合适时机响应中断，转入内核中断服务程序。
5. 中断服务程序从控制器数据寄存器取数据，再送入主存缓冲区。
6. 服务程序更新 I/O 状态，必要时唤醒等待进程。

中断方式解决了查询方式的忙等问题，但每个字或字符仍要经过 CPU。若高速设备频繁中断，CPU 会把大量时间花在中断响应、保护现场、恢复现场和服务程序上。

| 项目 | 中断驱动方式 |
| --- | --- |
| CPU 干预频率 | 高，启动 I/O 和每次数据就绪后都要介入 |
| 传输单位 | 通常每次一个字或字符 |
| 读数据流向 | 设备 $\rightarrow$ 控制器 $\rightarrow$ CPU $\rightarrow$ 主存 |
| 写数据流向 | 主存 $\rightarrow$ CPU $\rightarrow$ 控制器 $\rightarrow$ 设备 |
| 主要优点 | CPU 不必忙等，CPU 与设备可并行工作 |
| 主要缺点 | 数据仍经过 CPU，频繁中断有明显开销 |

# DMA 方式


DMA 是 Direct Memory Access，直接存储器存取。它适合高速块设备。

**主存与 I/O 设备之间的数据传送不再经过 CPU，而由 DMA 控制器控制**。CPU 只在传输开始前做预处理，在传输结束后通过中断做后处理。

![1000](../assets/dma-controller-structure.svg)

DMA 控制器常见部件：

| 部件 | 作用 |
| --- | --- |
| 数据寄存器 `DR` | 暂存每次在设备与主存之间传送的数据 |
| 主存地址寄存器 `MAR` 或地址寄存器 `AR` | 保存当前要访问的主存地址，传送后自动修改 |
| 数据计数器 `DC` 或字计数器 `WC` | 记录还要传送多少数据，计数结束表示块传送完成 |
| 命令 / 状态寄存器 `CR` | 保存 CPU 发来的命令、传输方向和设备状态 |
| 控制与时序逻辑 | 协调 DMA 请求、总线请求、读写控制、计数和中断 |

[html-card height=720](../assets/dma-transfer-slides.html)

以数据输入为例，DMA 传送过程分成三段：

1. **传送前预处理**：CPU 向 DMA 控制器写入传输方向、主存起始地址、设备地址或端口、传送长度，然后启动设备和 DMA 控制器。
2. **传送中硬件控制**：设备准备好数据后向 DMA 控制器发 **DMA 请求**；DMA 控制器申请总线，取得总线控制权后，在设备与主存之间传送一个字或一个总线宽度的数据，并自动修改地址和计数。
3. **传送后中断通知**：一整块数据传完后，DMA 控制器向 CPU 发中断请求。CPU 转入内核做后处理，例如检查状态、释放缓冲区、唤醒等待进程。

| 项目       | DMA 方式                                    |
| -------- | ----------------------------------------- |
| CPU 干预频率 | 中，开始前设置参数，整块传完后处理中断                       |
| 传输单位     | 通常按块，块内每次总线传一个字或若干字节                      |
| 读数据流向    | 设备 $\rightarrow$ DMA 控制器 $\rightarrow$ 主存 |
| 写数据流向    | 主存 $\rightarrow$ DMA 控制器 $\rightarrow$ 设备 |
| 主要优点     | 数据不经过 CPU，适合高速块设备，CPU 与设备并行性高             |
| 主要缺点     | 需要 DMA 控制器；离散块或多缓冲区可能需要多次设置和中断            |

## DMA 请求

DMA 控制器需要访问主存时，向 CPU 或总线仲裁部件申请总线使用权。

CPU 不能在一次已经开始的访存中途交出总线，因此要先完成当前总线或存取周期，然后才停止后续访存并让出总线。

总线仲裁通常让 DMA 请求优先于 CPU 的访存。原因是外设按自身速率持续产生或消耗数据，控制器的缓冲区又有限；DMA 等待过久可能造成缓冲区溢出、欠载或数据丢失。CPU 却可以在周期边界暂停，寄存器和当前执行状态不会丢失，DMA 释放总线后即可继续执行。

> [!danger] DMA 请求 $\neq$ DMA 中断
> DMA 请求是 DMA 控制器申请取得总线使用权，CPU 在一个机器周期结束时进行响应，让出总线即可。
> DMA 中断是整块数据传送结束后由 DMA 控制器通知 CPU 执行后处理，CPU 在一条指令执行结束后进行响应并处理。

## CPU 与 DMA 的访存冲突

DMA 传送要访问主存，CPU 执行程序也可能访问主存。两者同时访问主存时会发生冲突，需要规定主存使用方式。

![1000](../assets/dma-memory-conflict.svg)

| 方式             | 做法                                     | 特点                       | 适用于               |
| -------------- | -------------------------------------- | ------------------------ | ----------------- |
| 停止 CPU 访问主存    | DMA 传送期间 CPU 暂停访存                      | 控制简单，但 CPU 利用率低          | 需要连续、成组高速传送的设备         |
| DMA 与 CPU 交替访存 | 把存取周期分给 CPU 和 DMA，例如 C1 给 DMA，C2 给 CPU | 不需要复杂的总线申请/归还，但硬件时序安排更复杂 | CPU 工作周期比主存存取周期长，且可固定分时的系统 |
| 周期挪用，也叫周期窃取    | DMA 需要访存时临时占用一个或几个存取周期                 | 常见且灵活；CPU 只在被挪用的周期受影响    | 设备请求间隔不固定的一般 DMA 系统 |

周期挪用有三种情况：

- CPU 此时不访问主存：DMA 直接使用主存周期。
- CPU 正在访问主存：等当前存取周期结束后，DMA 挪用后续周期。
- CPU 与 DMA 同时请求使用主存总线：DMA 优先，因为设备缓冲区可能溢出或欠载。

> [!example] 根据传送粒度计算周期挪用次数
> 某设备采用周期挪用 DMA 输入一个 $512B$ 的数据块，I/O 接口中的数据缓冲寄存器为 32 位。若设备每准备好一个寄存器宽度的数据，DMA 控制器就申请一次总线，则单次传送的数据量为：
>
> $$
> 32\ bit = 4B
> $$
>
> 完成整个数据块需要的数据传送次数为：
>
> $$
> \frac{512B}{4B}=128
> $$
>
> 因此，在题设的传送方式下，DMA 控制器需要进行 128 次数据传送，并相应地多次申请或占用主存周期。这里的“按块传送”是指 DMA 控制器负责完成整块任务，==不表示一次总线传输就搬完整个数据块==。
>
> 每次周期挪用只在 DMA 实际占用主存或总线的那个周期阻止 CPU 访存。该周期结束后，CPU 仍可继续执行和访存；CPU 并非在整个 $512B$ 数据块传送期间都不能访问主存。整块数据传完后，DMA 控制器再发出一次传送结束中断，通知 CPU 做后处理。

# 通道控制方式

通道是一种专门管理 I/O 的硬件部件，可以执行主存中的通道指令。

它类似于功能受限的 I/O 处理器。

通道既要从主存读取通道程序，又要控制设备与主存交换数据；如果 CPU 和通道共用系统总线或同一个主存端口，两者同时访存时仍要仲裁。

![1000](../assets/channel-control-flow.svg)

通道控制方式的大致流程：

1. CPU 指定主存中的通道程序。
2. CPU 执行 I/O 指令，告诉通道：通道程序在哪里、要操作哪个设备。
3. 通道执行通道程序，控制一个或多个控制器、设备完成一组 I/O 操作。CPU 可以去执行其他程序。
4. 通道完成任务后向 CPU 发中断。
5. CPU 做结束处理。

| 项目 | 通道控制方式 |
| --- | --- |
| CPU 干预频率 | 低，一组 I/O 任务开始和结束时介入 |
| 传输单位 | 一组块或一组 I/O 操作 |
| 数据流向 | 在通道控制下，设备与主存之间传送 |
| 主要优点 | CPU、通道、设备并行工作，适合大量设备统一管理 |
| 主要缺点 | 需要专门通道硬件，系统复杂；访问主存时仍可能与 CPU 争用共享资源 |

# CPU 用于外设的时间占比

计算 CPU 参与程度时，**可把观察时间统一为 $1\text{s}$，计算这一秒内 CPU 为该外设执行处理所花的总时间**：

$$
\text{CPU 时间占比}=\frac{\text{CPU 为该外设工作的总时间}}{1\text{s}}\times 100\%
$$

设外设数据率为 $R\,(B/s)$，即这一秒总任务量。程序查询或中断方式每次传送 $u\,B$，DMA 每块传送 $B_D\,B$，通道每项任务平均处理 $B_C\,B$。常见计算模型如下：

| 控制方式 | 一秒内 CPU 介入次数 | CPU 时间占比 |
| --- | --- | --- |
| 程序查询 | 查询 $f_q$ 次，另搬运 $R/u$ 次 | $\left(f_qt_q+\dfrac{R}{u}t_m\right)\times100\%$ |
| 中断驱动 | 中断并搬运 $R/u$ 次 | $\dfrac{R}{u}t_i\times100\%$ |
| DMA | 启动并结束处理 $R/B_D$ 块 | $\dfrac{R}{B_D}(t_s+t_f)\times100\%$ |
| 通道 | 启动并结束处理 $R/B_C$ 项任务 | $\dfrac{R}{B_C}(t_s+t_f)\times100\%$ |

其中，$t_q$ 是一次查询所需的 CPU 时间，$t_m$ 是 CPU 搬运一个传送单位的时间，$t_i$ 是一次中断响应、服务和数据搬运的总时间，$t_s$、$t_f$ 分别是启动和结束处理时间。程序查询若采用连续忙等，CPU 在等待设备期间几乎一直执行查询循环，因此在这段 I/O 时间内占比常接近 $100\%$。

> [!example] 用同一组数据比较四种方式
> 某系统的外设数据率为 $R=10^6B/s$。以 32 位为程序查询和中断方式传输单位，即 $u=4B$；程序查询采用连续忙等；中断方式每次中断处理耗时 $0.5\mu s$；DMA 每块 $1000B$，每块包含 $1000/4=250$ 次总线数据传送，CPU 对每块的启动与结束处理共耗时 $10\mu s$；通道每项任务处理 $10000B$，每项任务启动与结束处理共耗时 $20\mu s$。忽略 DMA 和通道与 CPU 的访存冲突，则：
>
> - 程序查询：连续忙等，CPU 时间占比接近 $100\%$；
> - 中断驱动：$\dfrac{10^6}{4}\times0.5\mu s=0.125$，占 $12.5\%$；
> - DMA：$\dfrac{10^6}{1000}\times10\mu s=0.01$，占 $1\%$；
> - 通道：$\dfrac{10^6}{10000}\times20\mu s=0.002$，占 $0.2\%$。
>
> 同一数据率下，传送单位越大、一次 CPU 介入能交付给硬件的工作越多，CPU 时间占比通常越低。若计算结果超过 $100\%$，说明该方式所需的 CPU 时间已经超过一秒内可提供的时间，系统无法持续维持题设数据率。

> [!note] 忽略访存冲突
> 上式只统计 CPU 的预处理和结束处理时间，不把 DMA 挪用的主存周期计入 CPU 时间。若题目要求考虑周期挪用，还要另外计算 DMA 占用总线或主存端口造成的 CPU 停顿时间。

# 四种方式总表

| 控制方式 | 完成过程                                                   | CPU 干预频率 | 传输单位       | 数据流向                                          | 适用于       |
| ---- | ------------------------------------------------------ | -------- | ---------- | --------------------------------------------- | --------- |
| 程序直接控制 | CPU 按确定时机直接传送，或查询状态后传送；每个传送单位都由 CPU 搬运 | 极高 | 字 / 字符 | 设备 $\leftrightarrow$ CPU $\leftrightarrow$ 主存 | 时序可预知或简单低速设备 |
| 中断驱动 | CPU 发命令后去做别的事，设备准备完成后中断 CPU，CPU 搬数据。每搬一次数据就要中断 CPU 一次。 | 高        | 字 / 字符     | 设备 $\leftrightarrow$ CPU $\leftrightarrow$ 主存 | 低速或少量数据设备 |
| DMA  | CPU 设置参数，DMA 控制器搬运一整块，完成后中断 CPU 。                      | 中        | 块          | 设备 $\leftrightarrow$ 主存                       | 高速块设备     |
| 通道   | CPU 启动通道程序，通道控制**一组** I/O 操作，完成后中断 CPU                 | 低        | 一组块 / 一组操作 | 设备 $\leftrightarrow$ 主存                       | 大量设备、大型系统 |
