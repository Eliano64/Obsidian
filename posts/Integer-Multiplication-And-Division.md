# 乘法

乘法运算常见有三类实现方式：

| 实现方式   | 基本思路                                                                            |
| ------ | ------------------------------------------------------------------------------- |
| 迭代式乘法器 | 复用同一个 ALU 和寄存器，每轮根据乘数位决定加、减或不操作，再移位。若一次ALU加法和一次移位各需要一个时钟周期，则对于$n$位乘法需要$2n$个时钟周期 |
| 阵列乘法器  | 用大量并行硬件同时生成并累加部分积，可在一个时钟周期内完成一次乘法运算。速度最快但硬件开销大。                                 |
| 移位-加减法 | 从算法层面把乘法转化为移位、加法、减法，硬件成本最低但速度最慢                                                 |

下面介绍的即**迭代式乘法器**

## 无符号乘法

乘法过程可以用三个核心寄存器理解：

| 寄存器              | 作用                 |
| ---------------- | ------------------ |
| 累加器（累加寄存器） `ACC` | 初始为全 `0` ，保存部分积的高位 |
| 乘商寄存器 `MQ`       | 初始保存乘数，运算结束后保存乘积低位 |
| 运算器内部操作数寄存器 `X`  | 保存被乘数              |

乘法的流程是：

1. 看 `MQ` 的最低位。
2. 若最低位为 `1`，则 `ACC = ACC + X`。
3. 若最低位为 `0`，则 `ACC` 不变。
4. 将 `进位（若有）|ACC | MQ` 整体逻辑右移一位。
5. 重复 n 次后，`ACC | MQ` 中保存完整乘积。

> [!note] 
> 若 `ACC + X` 产生进位，进位也要参与后续右移。

[html-card height=760](../assets/integer-multiplication-shift-add.html)


若两个 n bit 无符号整数相乘，完整乘积最多需要 2n bit 表示。

例如两个 8 bit 无符号整数：

$$
255 \times 255 = 65025
$$

这个结果需要 16 bit 才能完整保存。

> [!warning] 乘积位数
> n bit 与 n bit 相乘，结果不一定还能放进 n bit。若只保留低 n bit，高位会被截断。

## 有符号乘法

有符号整数使用**Booth 算法**处理补码乘法。

每轮 Booth 乘法的核心流程是：

1. 查看 MQ当前的最低位$MQ_{0}$与其**右**边的 $MQ_{-1}$(上一轮移出去的$MQ_{0}$，初始值为0)。
	1. 若为 `01`，则 `ACC = ACC + X`。
	2. 若为 `10`，则 `ACC = ACC - X`。
	3. 若为 `00` 或 `11`，则 `ACC` 不变。
2. 将 `ACC | MQ | MQ_{-1}` 整体**算术右移**一位。
3. 重复 n 次后，`ACC | MQ` 保存补码乘积。

引入$MQ_{0}MQ_{-1}$的思想是：把连续的 `1` 看成由最高位左移一位表示的二进制数，减去最低位表示的二进制数的差。所以若为 `01` 则说明遇到了连续的 `1` 的最高位，故加上 `X` ；若为 `10` 则说明遇到了连续的 `1` 的最低位，故减去 `X` 。

> [!example]
01001B = +10000B - 1000B + 10B - 1B
>
原本连续多个 `1` 需要多次加法；Booth 算法只在边界处做加减。`00` 和 `11` 都说明当前没有遇到边界，所以不操作。

[html-card height=820](../assets/integer-multiplication-booth.html)

> [!important] Booth 算法为什么能处理有符号数
> 补码的符号位本来就有负权重。Booth 算法用“加一段的开始、减一段的结束”来重写乘数的权重展开，因此可以直接在补码位串上得到有符号乘积。

# 除法

进入除法过程前，必须先做入口判定：

1. 若除数为 0，除法无定义，引起**除0异常**，不能启动除法运算。
2. 若 $|被除数| < |除数|$，商为 0、余数为被除数，直接结束。

只有这些情况都排除后，才需要进入逐位试减的除法过程。也就是**恢复余数除法**。

使用寄存器说明如下。

| 寄存器              | 作用                   |
| ---------------- | -------------------- |
| 累加器（累加寄存器）`ACC`  | 初始为全 `0`，保存部分余数，最后保存余数       |
| 乘商寄存器 `MQ`       | 初始保存被除数，低位在运算过程中逐步改写为商 |
| 运算器内部的操作数寄存器 `X` | 保存除数                 |

每轮左移时，`MQ` 中尚未处理的被除数最高位移入 `ACC`；试减结果则作为新的商位写入 `MQ` 最低位。

恢复余数除法的核心流程是：

1. 将 `ACC | MQ` 整体左移一位。
2. 试做 `ACC = ACC - X`。
	1. 若 `ACC` 非负，说明够减，在 `MQ` 最低位写入 `1`。
	2. 若 `ACC` 为负，说明不够减，执行 `ACC = ACC + X` 恢复原来的部分余数，并在 `MQ` 最低位写入 `0`。
3. 重复 n 次后，`MQ` 中保存商，`ACC` 中保存余数。

> [!note] 试减需要判断正负
> 恢复余数除法中，`ACC - X` 的结果可能为负。为了判断是否够减，通常为 `ACC` 增加一个判断符号所需的扩展位。

> [!warning] 商溢出
> 商溢出发生在商形成或结果写回阶段。若最终得到的商无法放入目标商寄存器，就不能按正常结果写回，应触发**商溢出异常**。

[html-card height=760](../assets/integer-division-shift-subtract.html)

以上是无符号数的除法的过程。

有符号除法一般先对绝对值做无符号除法，再根据操作数的符号恢复商和余数的符号，结果按补码保存。

若结果超出补码可表示范围，也会发生商溢出；典型情况是 n bit 补码的最小负数除以 `-1`。
