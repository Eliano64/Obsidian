# 交换类排序

交换类排序的工作思想是：根据两个元素关键字的比较结果，交换它们在序列中的位置。

- **冒泡排序**：只比较相邻元素，若相邻逆序则交换。
- **快速排序**：通过一次划分把枢轴放到最终位置，再递归处理左右子表。

# 冒泡排序

**冒泡排序**从后往前或从前往后两两比较相邻元素。如果相邻元素逆序，就交换它们。一趟冒泡结束后，可以保证当前未达到最终位置的最大的元素到达最终位置，所以冒泡排序最多只需要比较 $n-1$ 趟。

如果第$m$次处理无交换发生，则说明已经有序，停止。

由于仍需要这个第 $m$ 次作为检查才能确定排序结束，所以即使实际上最后一次交换发生在第$m-1$次处理，我们仍认为排序趟数是$m$。

## 冒泡排序的 C 写法

```c
/**
 * Sorts an integer array in nondecreasing order using bubble sort.
 *
 * Args:
 *   a: Array to sort in place.
 *   n: Number of elements in the array.
 *
 * Notes:
 *   This version scans from right to left. After pass i, a[0..i] contains
 *   the i+1 smallest elements in final order.
 */
void bubble_sort(int a[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int swapped = 0;  // 本趟是否发生交换，用于提前结束

        for (int j = n - 1; j > i; j--) {
            if (a[j - 1] > a[j]) {
                int temp = a[j - 1];
                a[j - 1] = a[j];
                a[j] = temp;
                swapped = 1;
            }
        }

        if (!swapped) {
            break;        // 本趟无交换，说明整体已经有序
        }
    }
}
```

这段代码只在 `a[j - 1] > a[j]` 时交换。若两个元素相等，不交换，所以冒泡排序稳定。

## 冒泡排序的时间复杂度和空间复杂度

| 情况 | 比较次数 | 交换次数 | 时间复杂度 |
|---|---:|---:|---:|
| 最好，原本有序 | $n-1$ | $0$ | $O(n)$ |
| 最坏，原本逆序 | $\frac{n(n-1)}{2}$ | $\frac{n(n-1)}{2}$ | $O(n^2)$ |
| 平均 | $O(n^2)$ | $O(n^2)$ | $O(n^2)$ |

空间复杂度为 $O(1)$。

## 冒泡排序与链表

冒泡排序可以用于链表。

如果在链表中从前往后冒泡，每一趟可以把较大的元素冒到链尾。链表结点之间不能像数组那样按下标直接访问，但冒泡只需要顺着 `next` 比较相邻结点，因此可以实现。

不过链表冒泡仍然要多趟相邻比较，时间复杂度仍是 $O(n^2)$。

# 快速排序

0. 若数组只有 1 个元素或没有元素，则直接退出。
1. 对整个数组进行划分。快速排序的一次划分过程：
	1. 在待排序区间中选一个元素作为枢轴 `pivot`，这里采用首元素作为枢轴。
	2. 通过一次划分，使枢轴左侧元素都小于 `pivot`，右侧元素都大于等于 `pivot`。
		* 笔算模拟划分：
			1. 不看枢轴，左手指向从左到右第一个大于等于枢轴值的元素，右手指向从右到左第一个小于枢轴值的元素。若左右手没有交叉，就交换这两个放错分区的元素，继续扫描，直到左右手相遇。
			2. 设枢轴为 `p` , 应当在枢轴左侧的子数组为 `A` ，右侧的为 `B` 。现在整个数组是 `p | A | B` 。
			3. 把 `p` 放到 `A`、`B` 之间，得到 `A | p | B`。不必整理 `A`、`B` 的内部次序；原地实现时，可以直接交换 `p` 与 `A` 的最后一个元素。
	3. 枢轴被放到最终位置。可见一次划分至少可以确定 1 个最终位置。
2. 对枢轴左右两个子表分别进行快速排序。

## 快速排序的 C 写法


```Cpp
inline int partition(int *A, int lo, int hi) {
	int pivot = A[lo];
	int i = lo;
	int j = hi;
	// [lo, i], [i + 1, j), [j, hi)
	// A[lo]       == pivot
	// A[lo+1, i]  < pivot
	// A[i+1, j)   unknown
	// A[j, hi)    >= pivot

	while(i + 1 <j){
		// i and j may move in either order.
		while(i + 1 < j&&A[i + 1]<pivot) ++i;
		while(i + 1 < j&&A[j - 1]>=pivot) --j;
		if(i + 1 < j){
			swap(A[i+1],A[j - 1]);
		}
	}
	// The unknown region is empty.
	// A[lo] == pivot, A[lo+1...i] < pivot.
	// Therefore, A[i] is the last element that belongs to the left part.
	swap(A[i],A[lo]);
	return i;
}

void quickSort(int *A, int lo, int hi) {
    if (lo + 1 >= hi) {
        return;
    }
    int mi = partition(A, lo, hi);
    quickSort(A, lo, mi);
    quickSort(A, mi+1, hi);
}
```


在 `Partition`内部每次刚进入循环时，$A$有 3 个部分：

$$
[lo, i], [i + 1, j), [j, hi)
$$

其中，第一个区间包含枢轴以及已经确认小于枢轴的元素；第二个是尚未确认的区间；第三个区间中的元素都大于等于枢轴。

这 3 个区间的语义恒定，这就是**循环不变量。**

我们要做的就是逐步探索、逐步扩大已知的第一个和第三个区间，缩小未知第二个区间。

`j` 向左移动，逐步扩大右侧已确认区间；`i` 向右移动，逐步扩大左侧已确认区间。若两侧各发现一个放错分区的元素，就交换它们。

就这样一直移动直到满足语义的区间无法再扩大。此时，`A[i+1]` 是从左到右遇到的第一个大于等于 $pivot$ 的元素，`A[j-1]` 是从右到左遇到的第一个小于 $pivot$ 的元素。若未知区间仍存在，就交换二者，使它们分别进入正确的分区，再继续移动两指针。

一直这样操作，直到未知区间不存在为止。这个时候将 `A[lo]` 与 `A[i]` 交换。

于是 $pivot$ 左侧所有元素都小于它，而右侧所有元素都大于等于它，$pivot$ 落在了最终位置。

## 快速排序的时间复杂度和空间复杂度

对所有尚未确定最终位置的区间都处理一遍称为一趟排序。

若把第一次对整个序列的划分记为第 1 层，那么趟数就是实际执行划分的递归层数；只包含 0 个或 1 个元素、直接返回的递归调用不另算一趟。

快速排序的时间和空间都与趟数（递归层数）有关。

> [!Danger] 一次划分 $\ne$ 一趟快速排序
> 一次划分只确定一个枢轴的最终位置；而对所有尚未确定最终位置的区间都处理一遍称为一趟排序。一趟排序可能确定多个枢轴位置。

[html-card height=620](../assets/quicksort-recursion.html)

每一层所有子表的划分总工作量不超过 $O(n)$，所以：

$$
\text{时间复杂度}=O(n \times \text{递归层数})
$$

递归工作栈的深度就是递归层数，所以：

$$
\text{空间复杂度}=O(\text{递归层数})
$$

若把快速排序的递归过程看成一棵二叉树：

- 最好情况：每次枢轴都把序列均匀分成两半，递归树高度约为 $\lfloor \log_2 n \rfloor + 1$。
- 最坏情况：每次枢轴都落在最边上，递归树退化为一条链，高度为 $n$。

因此：

| 情况  |            趟数 |          时间复杂度 |         空间复杂度 |
| --- | ------------: | -------------: | ------------: |
| 最好  | $O(\log_2 n)$ | $O(n\log_2 n)$ | $O(\log_2 n)$ |
| 平均  | $O(\log_2 n)$ | $O(n\log_2 n)$ | $O(\log_2 n)$ |
| 最坏  |        $O(n)$ |       $O(n^2)$ |        $O(n)$ |

若初始序列已经有序或逆序，并且每次都取首元素为枢轴，那么每次划分都极不均匀，快速排序性能最差。

## 最好情况下关键字比较次数

最好情况下，每次枢轴都把当前序列尽量均分。

一次划分长度为 $n$ 的表时，枢轴要与其他元素比较，数量级为 $n-1$ 次。因此比较次数$C(n)$可以按递推式理解：

$$
C(0)=C(1)=0
$$

$$
C(n)=C(\lfloor \frac{n-1}{2}\rfloor)+C(\lceil \frac{n-1}{2}\rceil)+(n-1)
$$


> [!example] 
> $n=7$ 且每次正好均分：
> $$\begin{align}
> C(7)&=7-1+2C(3) \\
> C(3)&=3-1+2(1) \\
> C(1)&=0 \\
> \implies C(7)&= 10
> \end{align}$$

## 快速排序不稳定

快速排序不稳定。

例：

```text
2a 2b 1
```

若取 `2a` 为枢轴，一次划分后可能变成：

```text
1 2b 2a
```

两个关键字都为 2 的记录相对次序从 `2a, 2b` 变成 `2b, 2a`，所以快速排序不稳定。
